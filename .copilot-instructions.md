# Sudoku Application Refactoring Guidelines

## Project Overview
Refactoring a legacy Sudoku 9x9 application to modern standards using ES6+, React, and Next.js with Tailwind CSS.

## Technology Stack
- **Framework**: Next.js (latest stable version)
- **Language**: JavaScript/TypeScript (ES6+)
- **UI Library**: React with Hooks
- **Styling**: Tailwind CSS
- **Build Tool**: Next.js built-in

## Code Standards

### JavaScript/TypeScript
- Use ES6+ features: arrow functions, destructuring, template literals, async/await
- Use functional components with React Hooks (useState, useEffect, useContext)
- Prefer const/let over var
- Use optional chaining (?.) and nullish coalescing (??)
- Implement proper error handling and validation

### React Component Structure
- Create functional components with proper prop typing
- Use custom hooks for reusable logic
- Keep components focused and single-responsibility
- Use React Context for global state management where appropriate
- Implement proper component composition and props drilling avoidance

### Next.js Best Practices
- Use app router (App Directory) structure
- Implement proper file-based routing
- Use server components where possible
- Create API routes in `app/api/` directory
- Optimize images with next/image component
- Implement proper SEO with metadata

### Tailwind CSS Styling
- Use Tailwind utility classes for all styling
- Avoid inline styles
- Use responsive design with Tailwind breakpoints (sm, md, lg, xl)
- Create reusable component patterns with @apply if necessary
- Follow a consistent color palette and spacing scale

## Refactoring Priorities
1. Break monolithic sudoku.js into modular components
2. Separate game logic into custom hooks and utilities
3. Create reusable React components for board, cells, and controls
4. Implement Tailwind CSS for all styling
5. Add form validation and error handling
6. Implement game state management (useState, useContext, or zustand if needed)

## Code Quality
- Write clean, readable, self-documenting code
- Add JSDoc comments for complex functions
- Use meaningful variable and function names
- Implement proper loading and error states
- Add input validation and user feedback

## Performance Considerations
- Use React.memo for non-state dependent components
- Implement proper key props in lists
- Avoid unnecessary re-renders
- Optimize game solver algorithm if needed

## Accessibility (A11y)
- Use semantic HTML elements
- Add proper ARIA labels
- Ensure keyboard navigation support
- Maintain sufficient color contrast
- Test with screen readers

## Testing Recommendations
- Unit tests for game logic utilities
- Component tests for React components
- Integration tests for game flow
- Use Jest and React Testing Library
